1. SYSTEM PROMPT TEMPLATE (app.py)
================================================================================

You are a helpful FYP Handbook assistant for FAST-NUCES students. 

IMPORTANT RULES:
1. Answer ONLY using information from the provided context chunks
2. ALWAYS cite page numbers using the format (p. X) after claims
3. If the context doesn't contain the answer, say "I don't have that information in the handbook"
4. Do NOT make up information or use external knowledge
5. Be concise but complete in your answers
6. Quote key phrases when helpful, but also paraphrase to explain clearly

Question: {question}

Context from FYP Handbook:
{context}

Answer (with page citations):

================================================================================
EXPLANATION:
- This is the main prompt template used for generating answers
- Variables {question} and {context} are filled dynamically
- Emphasizes grounding (only use context), citation (page numbers), and accuracy
- Instructs the model to be helpful but honest about limitations

================================================================================
2. CONTEXT FORMATTING TEMPLATE
================================================================================

[Chunk {chunk_number} - Page {page_number}]
{chunk_text}

================================================================================
EXPLANATION:
- Each retrieved chunk is formatted with this template
- Provides clear page attribution for each piece of context
- Multiple chunks are concatenated with newlines between them
- Example:
  [Chunk 1 - Page 5]
  The FYP report must use Times New Roman 11pt for body text...
  
  [Chunk 2 - Page 6]
  Margins should be set to: Top 1.5", Bottom 1.0", Left 2.0", Right 1.0"...

================================================================================
3. REJECTION PROMPT (Low Similarity)
================================================================================

⚠️ I don't have that information in the handbook. The retrieved content has low 
similarity to your question.

Try rephrasing your question or asking about topics covered in the FYP handbook.

================================================================================
EXPLANATION:
- Triggered when max similarity score < SIMILARITY_THRESHOLD (default: 0.25)
- Prevents hallucination by refusing to answer when relevance is low
- Provides constructive feedback to help user rephrase

================================================================================
4. QUERY PREPROCESSING
================================================================================

No preprocessing is applied to user queries. Queries are embedded directly
using the Sentence-BERT model (all-MiniLM-L6-v2).

Rationale:
- Preserves user's natural language and intent
- Model is trained to handle various phrasings
- Simple approach reduces complexity and potential errors

================================================================================
5. EMBEDDING PROCESS
================================================================================

Steps for Query Embedding:
1. User query → String input
2. SentenceTransformer.encode(query) → 384-dimensional vector
3. faiss.normalize_L2(embedding) → Normalized for cosine similarity
4. FAISS search → Retrieve top-k most similar chunks

Similarity Calculation:
- FAISS uses L2 distance after normalization
- Conversion to cosine similarity: similarity = 1 - (L2_distance² / 2)
- Range: 0.0 (no similarity) to 1.0 (identical)

7. CONFIGURATION PARAMETERS
================================================================================

Chunking Configuration:
- CHUNK_SIZE: 300 words
- OVERLAP: 30% (90 words overlap between chunks)
- MIN_CHUNK_SIZE: 50 words (chunks smaller than this are skipped)

Retrieval Configuration:
- MODEL_NAME: 'all-MiniLM-L6-v2'
- EMBEDDING_DIMENSION: 384
- TOP_K: 5 (number of chunks to retrieve)
- SIMILARITY_THRESHOLD: 0.25 (minimum similarity for valid results)

Search Configuration:
- SIMILARITY_METRIC: Cosine similarity (via normalized L2)
- INDEX_TYPE: FAISS Flat L2 (exhaustive search, exact results)

================================================================================
8. PROMPT DESIGN RATIONALE
================================================================================

Key Design Decisions:

1. **Strict Grounding**: "Answer ONLY using information from the provided context"
   - Prevents hallucination and ensures factual accuracy
   - Critical for educational/reference applications

2. **Mandatory Citations**: "ALWAYS cite page numbers using the format (p. X)"
   - Enables verification against source document
   - Builds trust and transparency
   - Helps students locate information in original handbook

3. **Honesty About Limitations**: "If the context doesn't contain the answer..."
   - Better to admit ignorance than provide incorrect information
   - Guides users to rephrase or ask different questions

4. **Balanced Detail**: "Be concise but complete in your answers"
   - Respects user's time while ensuring comprehension
   - Particularly important for quick reference queries

5. **Helpful Formatting**: Using quotes and paraphrasing
   - Quotes preserve exact requirements (e.g., "Times New Roman 11pt")
   - Paraphrasing explains complex concepts clearly
   - Combination provides both precision and understanding

================================================================================
10. ERROR HANDLING PROMPTS
================================================================================

Case 1: Empty Query
→ No prompt generated, UI shows: "Please enter a question"

Case 2: No Relevant Results (similarity < threshold)
→ "⚠️ I don't have that information in the handbook. The retrieved content has 
    low similarity to your question."

Case 3: Index Not Found
→ "❌ Index not found! Please run `ingest.py` first to process the handbook."

Case 4: Out-of-Scope Query (e.g., "What's the weather?")
→ Context will have low similarity → triggers Case 2 response
